    IMAS Core¶

    IMAS-Core (formerly known as the Access-Layer Low-Level) is a low-level C++ library that abstracts the details of the data storage on disk (or different data sources) from the end-user IDS API like IMAS-Python, IMAS-Fortran, IMAS-MATLAB, IMAS-Cpp and IMAS-Java (previously referred to as the Access-Layer High-Level Interfaces).

    While most users may never directly call the IMAS-Core API, it is useful to know about some of its concepts and to learn how to configure and install it.

    Concept and terminology¶

    Abstracting data storage details from the API used by users in their code allows to easily switch from a given I/O store to another, giving more flexibility without complexifying the application. IMAS-Core provide the following key elements:

    • IMAS data is organized in a data entry that comprises one or more IDS types to describe a simulation results or a pulse;

    • A C-based API for portability to other programming languages;

    • The API consist in context management functions (start operation at a data entry, IDS or array of structure levels) and functions for actual read/write operations (reading and writing all the supported data types: integers, floating points, characters, complex);

    • The data entry API relies on a URI syntax to ensure flexibility and extensibility;

    • A Cython-based binding of the API for Python;

    • Several (optional) backends with their own specificities: hdf5, mdsplus, uda, ascii, memory, flexbuffers.

    Info: The IMAS-Core is generally not aware of the internals of IDS structure's details, so it does not depend on IMAS-Data-Dictionary. There are two exceptions: at build time when using the mdsplus backend which needs models to be generated for a given version of the DD, and at runtime when using the uda backend with its default cache_mode=ids option.

    Configuration and install¶

    Building from sources with CMake offers easy control on all configuration options and let you decide which optional backends (and their respective dependencies) and bindings (Python) you want to support.

    For easier startup with Python applications, IMAS-Core can now be installed from sources with pip. Note that it is using scikit-build to interact with CMake, so if you don’t want the default configuration options you will need to pass CMake options via pip with the -C skbuild.cmake.define.OPTION=VALUE syntax.

    But it can get even simpler than that as an imas-core Python package is also available on PyPI for Linux, MacOSX (arm) and Windows.

    Install of the package¶

    %pip install imas-core
import imas_core
print(f"installed version of IMAS-Core = {imas_core.__version__}")

    Simple test with HDF5 backend¶

    This test allow us to take a look at how files are organized in a data entry. First, all files related to a given data entry are stored inside the same folder. In case of the hdf5 backend, you will find in this folder a master.h5 which will contains one or several links to individual IDS files named as <idsname>.h5 (e.g. equilibrium.h5, wall.h5, pf_active.h5, …) and <idsname>_<occurrence>.h5 in case you have several occurrences of the same IDS type (e.g. equilibrium_1.h5).

    # now creating a new data-entry using the HDF5 backend 
# note that you will never use this API as an end-user
imas_core._al_lowlevel.al_begin_dataentry_action("imas:hdf5?path=./testh5",
                                                 imas_core.al_defs.CREATE_PULSE)
!ls -l ./testh5

    total 4
-rw-r--r-- 1 runner runner 8 Nov 23 14:30 master.h5

    Test with MDSplus backend¶

    Other backends will use different files and names but these files will still belong the a unique folder. E.g. with the mdsplus backend, the folder will contain always (and only) three files: ids_001.characteristics, ids_001.tree (these are set by the models) and ids_001.datafile that contains the data values.

    Info: Unfortunately, at the moment the Python Wheel does not contain the MDSplus backend as show below, so you will currently have to build imas_core from sources to enable this backend. Note that the uda backend is also present in the Linux package but not yet for MacOSX or Windows.
    # verifying that indeed the mdsplus backend is not part of this package
# so it won't create the targeted folder for the data entry!
imas_core._al_lowlevel.al_begin_dataentry_action("imas:mdsplus?path=./testmds",
                                                 imas_core.al_defs.CREATE_PULSE)
!ls -l ./testmds

    ls: cannot access './testmds': No such file or directory

    ERROR:root:b'al_begin_dataentry_action: [ALBackendException = MDSplus backend is not available within current install]'
